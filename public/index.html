01   ABSTRACT

What We Built

This project presents the design and development of a SCARA (Selective Compliance Assembly Robot Arm) based FDM 3D printer, integrated with an IoT monitoring system. The primary objective was to develop a cost-effective robotic arm based FDM 3D printer capable of providing better motion flexibility and a larger workspace compared to conventional gantry-based 3D printers.

Conventional gantry-based printers are fundamentally constrained by their Cartesian frame — restricted to a fixed build volume, unable to handle complex overhanging geometries without support material, and offering no remote visibility into the printing process. The SCARA architecture directly addresses these limitations through its R-R-P (Revolute-Revolute-Prismatic) kinematic configuration: two revolute joints controlling the X-Y plane position and one prismatic joint controlling the Z-axis, delivering 3 degrees of freedom and a circular working workspace significantly larger than the machine's physical footprint.

The printer structure is mostly 3D-printed from PETG filament — chosen for its superior thermal resistance and impact toughness over PLA — making it a low-cost, open-source platform. Motion control is handled by an Arduino Mega 2560 with RAMPS 1.4 running customised Marlin firmware with SCARA inverse kinematics. Four NEMA 17 stepper motors driven by TMC 2209 silent-step drivers provide smooth, precise motion. An ESP32 microcontroller handles IoT monitoring, streaming temperature and vibration data wirelessly to a local web dashboard. The project successfully demonstrated stable printing operation, functional inverse kinematics, and real-time IoT monitoring.

02   METHODOLOGY

How It Works

01
// DESIGN PHASE
CAD Model Design
The process begins with a 3D CAD model of the object to be fabricated. Using CAD software, the engineer defines all geometry, dimensional tolerances, wall thicknesses, and structural requirements. This stage is entirely virtual — no material is committed until the model is fully verified. The CAD model serves as the single source of truth for all downstream fabrication steps. For this project, the SCARA arm structure itself was CAD-designed first, stress-analysed using Von Mises analysis (confirming a safety factor of ~4 with PETG at 50 MPa yield strength), and then 3D-printed.

02
// PROCESSING PHASE
Slicing Software
The CAD model is imported into slicing software which translates the 3D geometry into printable layer-by-layer instructions. The slicer divides the model into thin horizontal cross-sections and calculates the optimal toolpath for the SCARA arm's extruder to trace. A key challenge specific to this project was that most slicer software is designed and optimised for Cartesian gantry printers — not for SCARA kinematics. Significant manual configuration was required to generate toolpaths compatible with the SCARA's rotational joint architecture. The slicer also determines print speed, layer height, extrusion width, and support structure requirements.

03
// CODE GENERATION
G-Code Generation
The slicer outputs a G-code file — a standardised sequence of motion commands encoding every instruction the printer needs: coordinates, extrusion amounts, travel speeds, and temperatures. For this SCARA system, the G-code's Cartesian X-Y coordinates are fed into the Marlin firmware's SCARA inverse kinematics solver, which in real-time converts each position into the corresponding angular values for Joint 1 and Joint 2. The firmware was configured with the exact SCARA linkage lengths (L1 = 228 mm, L2 = 136.5 mm), gear reduction ratios (20:1 and 16:1), and homing offsets — a process requiring extensive manual calibration.

04
// EXECUTION PHASE
SCARA Arm Execution
With G-code transmitted to the Arduino Mega 2560 + RAMPS 1.4 controller, the printing process begins. The Marlin firmware reads each G-code command and uses its SCARA inverse kinematics solver to compute the required joint angles in real-time. The TMC 2209 SilentStepStick motor drivers command the NEMA 17 stepper motors to rotate Joint 1 and Joint 2 to the calculated angles while the Z-axis prismatic joint rises steadily layer by layer. The E3D V6 hotend heats the filament to extrusion temperature and deposits it precisely along the calculated toolpath. Homing at startup — using X, Y, and Z endstops — establishes the SCARA's zero reference position before each print.

05
// MONITORING PHASE
IoT Monitoring — Continuous
Running in parallel throughout the print is the ESP32-based IoT monitoring subsystem. The ESP32 operates independently from the main Marlin controller, continuously reading two sensors: a SW420 vibration sensor mounted on the arm structure near the extruder, and a 100K NTC thermistor monitoring hotend temperature. The ESP32 hosts a local web server and uploads this sensor data wirelessly — the live readings are displayed on an ESP32 Sensor Dashboard accessible from any browser on the same Wi-Fi network, auto-refreshing every 2 seconds. This enables the operator to monitor temperature and vibration remotely without being physically present at the machine.

03   IoT MONITORING SYSTEM

ESP32 Dashboard

The IoT monitoring subsystem runs on a dedicated ESP32 microcontroller with built-in Wi-Fi, operating independently from the main 3D printing controller. This separation ensures the monitoring system does not interfere with the real-time motion control of the SCARA arm. The ESP32 hosts a local web server that displays live sensor data on a browser-accessible dashboard — auto-refreshing every 2 seconds — allowing the operator to supervise the printer remotely over Wi-Fi.

🌡️
Temperature Monitoring
A 100K NTC thermistor mounted on the E3D V6 hotend heater block continuously measures extruder temperature. The dashboard displays readings in both Celsius and Fahrenheit, alongside the NTC resistance value. This data helps detect thermal anomalies — under-heating causes clogging, over-heating degrades the filament. The same thermistor data is also used by Marlin for closed-loop temperature control during printing.
📳
Vibration Monitoring
A SW420 vibration sensor is mounted on the arm structure near the extruder. It uses a spring-based mechanism to generate a digital signal when vibration exceeds an adjustable threshold. The dashboard displays live SW-420 status. Excessive vibration during printing introduces dimensional inaccuracies and surface defects — monitoring it helps identify loose components, resonance issues, or calibration problems early.
🌐
ESP32 Web Server
The ESP32 hosts a local web server (ESP Webserver) accessible from any device on the same Wi-Fi network. The dashboard auto-refreshes every 2 seconds, displaying all sensor readings in real time. No external cloud subscription is required — the entire monitoring system operates on the local network. A live reading of 173.0°C / 343.5°F and vibration status "NONE" was confirmed during testing, validating the system's functionality.
⚡
Independent Architecture
The ESP32 monitoring system operates on a completely separate circuit from the Arduino Mega + RAMPS 1.4 printing controller. This ensures that the IoT subsystem's Wi-Fi communications and sensor polling do not introduce latency or interference into the time-critical stepper motor control and inverse kinematics calculations. Future work could integrate the two systems to enable automatic emergency shutdown on anomaly detection.

05   CONCLUSION

Closing Remarks

🎯

What We Achieved

Successfully designed, fabricated, and validated a SCARA robotic arm-based FDM 3D printing system with integrated IoT monitoring — all within a budget of PKR 55,912. The system demonstrated functional inverse kinematics, stable layer-by-layer extrusion, successful homing, and live sensor monitoring, confirming the feasibility of a low-cost open-source SCARA FDM platform.

🚀

Key Innovations

The core innovation is the SCARA R-R-P kinematic architecture replacing a conventional gantry, delivering a circular workspace of ~203,575 mm² with a 200 mm height — larger than the machine's physical footprint. The mostly-PETG-printed structure dramatically reduces manufacturing cost. The independent ESP32 IoT layer adds remote observability without affecting print performance.

📊

Challenges & Limitations

The most significant challenge was limited SCARA support in existing slicer and firmware software — extensive manual configuration of Marlin's SCARA settings, linkage lengths, gear ratios, and homing offsets was required. Vibration increased at higher arm speeds, and positioning accuracy was highly sensitive to linkage calibration. PETG structural parts exhibit some elastic deformation under load.

🔭

Future Work

Identified pathways include: closed-loop position feedback via encoders; development of SCARA-specific slicing software; true multi-axis printing with a tilting print surface; replacement of high-wear PETG components with carbon fibre; integration of ESP32 IoT with Marlin firmware for automatic emergency shutdown; and workspace expansion through extended arm links.
